# twitch-bots

ИИ-бот для Twitch-чата: читает сообщения, отвечает, когда к нему обращаются
(по слову-триггеру), помнит зрителей и разговаривает в заданном тобой характере.
Мозги — DeepSeek API (дёшево: доли цента за сотни сообщений).

## Что нужно получить перед запуском

### 1. Токен бота для чата Twitch

1. Зайти на https://twitchtokengenerator.com/
2. Выбрать **Bot Chat Token**
3. Авторизоваться Twitch-аккаунтом, который будет ботом (можно использовать
   свой основной аккаунт — тогда бот будет писать от твоего имени)
4. Скопировать **Access Token** — это и есть `TWITCH_BOT_TOKEN`

### 2. Ключ DeepSeek API

1. Зайти на https://platform.deepseek.com/api_keys
2. Зарегистрироваться, создать ключ
3. Пополнить баланс на пару долларов (хватит очень надолго — цены в разделе ниже)

## Установка

Окружение и `.env` — общие на весь монорепо, ставятся один раз из корня:

```powershell
cd ..\..
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
copy .env.example .env

# Только если нужен голос (~600 МБ моделей и бинарников)
.\.venv\Scripts\pip install -r requirements-voice.txt
```

Открой корневой `.env` и заполни:

- `TWITCH_BOT_TOKEN` — токен из шага 1
- `TWITCH_BOT_NICK` — имя аккаунта, который будет ботом
- `TWITCH_CHANNEL` — твой канал (куда бот будет подключаться)
- `DEEPSEEK_API_KEY` — ключ из шага 2
- `BOT_TRIGGER` — слово (или несколько слов через пробел), на которые бот
  будет реагировать, например `бот Марат`
- `BOT_PERSONALITY` — опиши характер бота своими словами, это главная настройка!
- `VOICE_ENABLED` — `true`, если хочешь ещё и говорить с ботом голосом
  через микрофон (см. раздел "Голосовой ввод" ниже)

## Запуск

Обычно бота запускают не отсюда, а кнопкой в панели (`apps/panel`, порт
8766) — она держит процесс сама. Вручную нужно для отладки.

Бот состоит из **двух независимых процессов** — Twitch-чат и голосовой
ввод запускаются отдельно (так надёжнее: вместе в одном процессе они
конфликтовали и падали). Держи открытыми оба окна во время стрима:

```powershell
# Обычный запуск — одна команда из корня репозитория, поднимает чат-бота,
# модерацию, панель и (если VOICE_ENABLED=true) голос дочерним процессом:
.\.venv\Scripts\python run.py

# Только чат-бот и модерация, без панели и без голоса — для отладки:
.\.venv\Scripts\python run.py --bot-only
```

Бот подключится к чату и будет отвечать, когда зрители пишут сообщение,
содержащее слово из `BOT_TRIGGER` (например "эй бот, как дела?").

## Голосовой ввод

Если `VOICE_ENABLED=true`, запусти дополнительно `voice_main.py` — он
слушает системный микрофон (устройство по умолчанию в Windows),
распознаёт речь **локально и бесплатно** через `faster-whisper` (модель
скачивается один раз при первом запуске, ~500 МБ, дальше работает
офлайн), и как только услышит слово-триггер, передаёт фразу боту в чат.

Распознанный текст передаётся между процессами через файл `voice_input.txt`
в папке проекта — это нормально, файл создаётся и очищается автоматически.

**Когда бот отвечает на голос.** Если в услышанной фразе есть его имя
(`VOICE_TRIGGER`) — отвечает всегда и сразу, без кулдауна и без требований
к длине фразы. Если имени нет — зависит от `VOICE_REQUIRE_TRIGGER`: при
`true` молчит совсем, при `false` изредка вставляет реплику (не чаще раза
в 35 секунд и только на фразы от трёх слов, чтобы не реагировать на шум).

Имя в `VOICE_TRIGGER` сравнивается нестрого, поэтому пиши корни без
окончаний (`марат шинр`): падежи («Марату», «Шинрой») и типичные ошибки
распознавания («Синра», «Шершень») ловятся сами. Список отдельный от
`BOT_TRIGGER` — в текстовом чате имя пишут правильно, там сравнение точное.

Особенности:
- Запись идёт непрерывно, распознавание — в фоне по одной фразе за раз.
  Раньше микрофон глушился на время распознавания, и речь, сказанная
  сразу после предыдущей фразы (~1.3 сек), терялась целиком — из-за
  этого бот через раз пропускал обращения по имени.
- Первый запуск скачивает модель — подключение к интернету нужно только
  один раз, дальше распознавание работает офлайн.

## Команды в чате

- `бот <вопрос>` (или как ты назвал триггер) — обратиться к боту
- `!botinfo` — бот расскажет, как к нему обращаться
- `!remember ник текст` — только для модераторов/стримера: запомнить факт
  о зрителе (например `!remember vasya любит спидраны`), бот будет
  учитывать это при ответах этому зрителю

## Как настроить характер бота

Всё завязано на `BOT_PERSONALITY` в `.env`. Пиши прямо как инструкцию:

```
BOT_PERSONALITY=Ты — саркастичный ИИ-помощник стримера по имени Нейра. Любишь подкалывать зрителей по-доброму, используешь эмодзи Twitch (Kappa, PogChamp). Отвечай коротко, максимум 2 предложения.
```

Можно менять в любой момент — просто отредактируй `.env` и перезапусти бота.

## Сколько это стоит

DeepSeek API считает по токенам (кусочкам текста). При активном чате
(несколько сотен обращений к боту за стрим) это выходит в районе
**десятков центов в месяц**, не больше. Бот сам обрезает ответы, чтобы
не тратить лишнее.

Хостинг не нужен — бот работает, пока запущен процесс на твоём ПК
(запускай перед стримом, останавливай Ctrl+C после).

## Структура проекта

```
main.py             — Twitch-чат: подключение, обработка сообщений, ответы
voice_main.py       — голосовой ввод: слушает микрофон, пишет в voice_input.txt
bot/config.py        — загрузка настроек из .env
bot/database.py      — память о зрителях и история чата (SQLite)
bot/brain.py         — обращение к DeepSeek API за ответом
bot/voice.py         — запись микрофона + распознавание речи (faster-whisper)
bot/voice_queue.py   — передача текста между двумя процессами через файл
```

## Анти-бот модерация

Движок живёт в [`../cigilbot`](../cigilbot), но работает **внутри этого
процесса**: main.py отдаёт ему каждое сообщение чата напрямую, если
`MODERATION_ENABLED=true`. Передача не блокирующая — событие уходит в
очередь в памяти, бот сразу читает следующее сообщение. Отдельно модерацию
запускать не нужно. Архитектура и настройка — в
[README самого Cigilbot](../cigilbot/README.md).

Панель управления — общая на оба проекта, [`../panel`](../panel), порт
8766: экран `/bots` для этого бота и `/moderation` для анти-спама, вход
один на оба.

## Ограничения текущей версии

- Бот отвечает только когда в сообщении встречается слово-триггер —
  это защищает от лишних затрат на API при большом чате.
- Память о зрителях сейчас — простое поле "заметка", а не полная история
  диалогов. Историю последних сообщений в чате бот видит (для контекста),
  но не хранит персональную "память" сверх заметок.
- Голосовой ввод слушает микрофон по умолчанию в системе — если нужно
  слушать другое устройство (например, конкретную гарнитуру), скажи,
  добавим выбор устройства в `.env`.
